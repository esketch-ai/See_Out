# Development Plan: 디자인 토큰 중재 및 문서 정합화

## 1. 중재 전략 (Arbitration Strategy)

단순 다수결(doc-authority)이나 현행 코드 고정이 아닌 **제3자 중재(Third-Party Mediation)** 를 채택한다. 중재 기준은 다음 4개 축이며, 우선순위 순으로 적용한다.

| 순위 | 중재 축 | 근거 | 관할 |
|---|---|---|---|
| 1 | **접근성 하한선** | WCAG 2.1 AA/AAA 정량 대비. 하한선을 미달하는 후보는 **재량과 무관하게 탈락** | 한수진 박사 (인지공학) |
| 2 | **전통 조형 정합성** | 실제 재료 색상(한지·먹·단청 비취·진사 주사·기증 황동)과의 물리적 부합도 및 채면 위 인지도 | 조성우 수석디자이너 |
| 3 | **기능 위계 정합성** | 동일 색상군의 3개 후보값은 모두 배제하지 않고 **단계(階) 위계로 재배치**하여 각 문서 의도를 보존 | 강민석 총괄 |
| 4 | **현행 코드 관용성** | 1~3위에서 분리되지 않을 때에만 코드 값을 유지 (하위 편향 원칙) | 개발팀 |

> **핵심 중재 기법 — 「배제」가 아니라 「재위상(再位相)」」**
> 비취록 3안(`#19382C` / `#243F35` / `#2D4F43`)은 색상환상(H) 157~159°로 동일 축 위에 놓여 있다. 즉 색상 논쟁이 아니라 **명도 단계 배정** 논쟁이다. 따라서 3개 값을 모두 폐기하지 않고 900/700/500 3단계로 재배치하여 3개 문서 의도를 동시에 충족시킨다. 황동 3안(H 37°)·인주 2안(H 3~5°)도 동일 전략을 적용한다.

- **Phase 6 (Pending — 차기 라운드)**: `tailwind.config.ts` 물리 분리 및 `tokens.ts` 단일 진실화. **`index.html` 인라인 설정 → 외부 파일 이전 작업 선행 필수.**

- **Phase 8 (Pending — 차기 라운드)**: 「창호살격」 기둥 실구현.

## 3. Testing & Verification Strategy

### 3.1 대비 측정 검증
- **방법**: WCAG 2.1 상대 휘도 상대비 산출식(`(L1+0.05)/(L2+0.05)`)에 의한 자동 계산. 본문·버튼 라벨은 4.5:1, 대제목·UI 경계는 3:1, AAA 표방 항목은 7:1.
- **기준**: 정본 문서 §6 「대비 검증 매트릭스」의 전 항목이 임계치를 충족해야 `Status: Approved` 로 승격된다.

### 3.2 회귀 방지 (코드 반영 단계 착수 시)
- **토큰 스냅샷 테스트**: `vitest` 에서 `tokens.ts` 값 스냅샷을 고정하여 임의 색상 변경을 차단.
- **금지 패턴 린트**: `bg-[#HEX]` · `text-[#HEX]` 형태의 임의 색상 사용을 ESLint 규칙으로 금지. Phase 7 완료 시 0건이어야 한다.
- **명명 검증**: `text-nobleGold-300` 처럼 정의되지 않은 색상 단계를 참조하는 클래스를 잡아내는 정적 검사 추가 (현행 `QuoteDiagnosticsWidget.tsx:280` 이 실제 위반 사례).

### 3.3 정문 일관성 검증
- **경력 표기**: 위원 경력은 `advisory-board-governance.md` 를 유일한 정본으로 하며, 다른 문서의 경력 수치는 부적합으로 플래그된다.
- **토큰 수치**: `tokens.ts` · `index.html` · `design-token-canonical-2026.md` 3자 간 수치 불일치 0건을 스크립트로 검사.
